01背景：为什么是现在

三件事同时发生，把「做动画讲解」的门槛从会做动画降到了会描述过程。

① 平台

浏览器原生有了 GPU 与 3D

WebGPU 已是 W3C Candidate Recommendation；Safari 26（2025-09）、Firefox 147 默认开启。 三维与 GPU 计算第一次不需要插件、不需要打包。

② 库

库的代价归零

一个 CDN 链接就能上 three.js。本 skill 连 npm 依赖都没有 —— 引擎 + 系统 Chrome 就是全部。

③ 模型

写代码不再是瓶颈

从「美术 + 剪辑 + 编程」降到写一份场景数据。 而场景数据是可 diff、可 lint、可被门禁管的。

02问题：PPT 的三个结构性缺陷

不是审美问题。改字体、改配色都修不掉。

丢

一屏 = 一帧

时间维度被丢掉了，观众要自己脑补顺序。

压

过程被压成一张图

而过程往往才是知识 —— 曲线的定义就是它的构造过程。

盲

好坏只能靠肉眼

改一版，你不知道是好了还是坏了。

03优势：四条，每条都有数

优势 1 / 确定性时间轴

render(t) 是纯函数

同一个时刻永远渲染出同一帧，不管你怎么跳、跳几次。场景里禁止 Date.now() / Math.random()。

换来四件事：可 scrub · 可截图断言 · 可逐帧导视频 · 评审可复现。
实测：同一 t 双渲染的差异 = 0 字节。

优势 2 / 过程可见

一笔一笔，顺序就是知识

12 行内核：画面 = f(笔画序列, 进度)。 笔尖只出现在正在画的那一笔上，观众始终知道"现在画到哪"。

已画好的笔画只增不减 —— 观众的短期记忆不用重载。

优势 3 / 注意力可控

信息按你的节奏释放

draw 逐笔 · spotlight/dim 聚焦 · countUp/morph 数字滚上去 · grow 图表按数据长大。

纪律：每 0.5 秒最多 3 个信息单元（G9 门禁）。一页塞八个要点同时弹出，一个都记不住。

优势 4 / 可验证

讲解质量可以被断言

15 项门禁在真浏览器里跑。不是"我看了一遍觉得还行"。

它们真的抓到过：笔尖"啪"地消失、四个元素同时弹出、旁白说不完、盒子里文字被裁掉。

门禁不只是防回归 —— 它能让作者发现自己看不见的问题。

04场景：有顺序，才值得逐笔

✅ 该用❌ 不该用（用别的更好）
讲机制：算法怎么算、管线怎么走、状态怎么变 要交付可在 PowerPoint 里继续编辑的 PPTX → 用 ppt-master / open-kimi-ppt
讲构造过程：一条曲线怎么被算出来、一个字形怎么从距离场浮出来 要可检索的参考资料 → 用文档
讲演进：架构怎么一步步长成今天这样 观众只有 30 秒、只要一个结论 → 一页大数字更有效
讲排查顺序：一次事故是怎么被定位的 只是并列的事实对比 → 一次给完，逐笔只是慢
判据只有一条：信息里有没有「顺序」。有顺序就逐笔，只是并列就一次给完。

0721 项门禁：凭什么说做完了

不是"我看了一遍觉得还行"。全部在 headless Chrome 里量真实 DOM 与像素。

门禁断言抓什么
G0CSS 里的每个 #id 必须在 DOM 里存在选择器写错 → 元素丢掉定位、退化成 grid 行、把舞台挤变形。这条门禁来自一次真实事故：三个 id 写错，舞台顶部被裁 17px
G0b主题落到 app 根：舞台/控制条/字幕条的 --bg 一致半截主题（浅色舞台配深色控制条）
G1能起来、校验器无错、console 无 error语法错、CDN 挂、初始化顺序错
G2 / G2b / G2c元素不越界 · 盒内文字不被裁切 · 文字层不重叠看不到图的作者最容易漏的一类
G2d三类遮挡实测为 0：覆盖层压内容 · 同一画布内标注互压 · 标注被画布裁掉「看起来有点遮挡」的全部三类。探测点必须包含每条旁白的时刻
G5b字幕恒为单行字幕换行 → 它占的安全带高度随文案变 → 作者没法定安全区
G11扰动元素声明的 data，画面必须跟着变装饰性画面：坐标硬编码的比例图，看着像回事但读不出任何一个值 —— 这是「内容简单」最深的根源
G3每一幕的早/晚截图必须不同；3D 区域裁剪截图也要不同静态 PPT 冒充动画、WebGL 黑屏
G4同一 t 两次渲染逐字节相同（含 canvas 像素签名）Date.now / Math.random 污染
G5每条旁白在其时刻字幕已显示且文字一致旁白与字幕错位
G6预测题：选项数、标对错、答错有解释、答案被记录点了没反应
G7每个 canvas2d 平均 alpha > 0draw() 没画东西
G8?three=off 后 3D 元素走 2D 降级且仍在动断网/内网时开天窗
G9每 0.5s 首次出现的信息单元 ≤ 3一页 8 个元素同时弹出（认知过载）
G9b同时生长的笔画 ≤ 4；生长时长占比 > 85% 报警一次画太多笔 / 一直画不停
G10标记 monotonic 的画布：可见笔画总长度只增不减画好的东西被擦掉、闪烁
G11扰动元素声明的 data：数值 ×1.6、分类数据去掉最后一项，画面必须变装饰性画面——看着像回事但读不出任何一个值
FRAMES / MP4一键出片：帧直接管道进 ffmpeg，不落盘视频链路是否真的通
G13图片必须真的解码成功（naturalWidth>0）且带 credit缺图开天窗、图片没标出处
G12出片后取两帧，量字幕带亮度：旁白时刻必须明显亮于无旁白时刻「声称字幕已烘焙、其实成片里没有」—— 这类只能靠量来防

一段值得记住的经历：G10 的度量改了三次

度量结果为什么错
alpha 之和报 8.9% / 2% 下降不透明的笔尖移开时，压在下面的半透明线露出来 → 度量伪影
像素足迹仍报 0.9% 下降笔尖自己就是一块不透明区域，它淡出必然减少足迹
可见笔画总长度全部通过只由笔画本身决定，对光标/光晕/装饰完全免疫 ✅

结论比门禁本身更重要：代理量会把"光标移动"和"内容被擦掉"混为一谈。要量你真正关心的那个量。

08这个 skill 的链路：素材 → 骨架 → 打磨 → 门禁 → 出片

它一开始只有「引擎 + 门禁」，缺了最前面那一环 —— 所以每份课件都从空文件手写，作者的注意力全花在坐标和画布上，内容自然停在「能跑」的水平。 from-md 就是补上的那一环。

环节做什么命令 / 判据
① 素材 → 骨架 把 Markdown（文档/论文笔记/复盘）变成能跑、能过全部门禁的课件骨架： 自动搭出 主张 / 机制 / 量级 / 边界 / 溯源（claim → 原文 file:line）， 并打印「待你补齐」的清单 node scripts/from-md.mjs doc.md --out=...
实测：抽出 88 个数字，生成物一次通过 16 项门禁
② 打磨内容 看体检表，把缺的补上：有数字 · 数字有参照 · 有边界。 把通用柱状图换成真正解释这件事的画法 node scripts/lint-scenes.mjs
输出每幕的深度体检表
③ 门禁 16 项浏览器门禁 + 静态 lint + 链接检查 ./scripts/check-all.sh
5 份课件全量约 60 秒
④ 出片 确定性时间轴逐帧 seek → 帧直接管道进 ffmpeg，不落盘 --mp4=out/x.mp4 --size=1920x1080

内容深度的可测定义

「内容简单」不是主观感受，是论证链缺环。每一幕都该有这五环， 其中三环已经被工具量化：

主张

一句可反驳的话

不是话题（"性能优化"），是判断（"CPU 侧比 GPU 侧更容易拿到大倍数"）。

机制 · G11 管

画面必须承载信息

扰动 data，画面必须跟着变。装饰性画面会被门禁直接抓住。

量级 · lint 管

数字 + 参照

有数字没有参照，观众不知道它是大是小。两者都要有。

边界 · lint 管

什么时候不成立

只有支持证据的讲解是宣传。边界句是可信度的来源。

推论

观众能自己算一步

预测题 + 可核对的溯源，让观众离开课件后还能推下去。

09怎么用

cd ~/.agents/skills/animated-lesson

./serve.sh                      # 预览（默认 :8099）
node scripts/lint-scenes.mjs    # 静态校验，毫秒级，作者循环里一直跑
node scripts/verify.mjs         # 15 项浏览器门禁

# 一键出片：帧直接管道进 ffmpeg，不落盘
node scripts/verify.mjs --deck='templates/deck.html?scenes=./scenes.mine.js' \
     --mp4=out/mine.mp4 --fps=24 --size=1920x1080
「按笔画」的价值是顺序，不是动起来。没有顺序信息时，动画只是慢。
边界：不做音频轨合成（TTS 走浏览器 speechSynthesis；导出视频无声、字幕已烘焙进画面）· 不做幕间转场（会掩盖内容，也让确定性截图变复杂）· three 只做静态场景 + 逐帧状态更新（要物理请自行接，但 t → 状态 必须是纯函数）· 验证器需要 Chrome（CI 里没有时只能跑静态 lint）。
