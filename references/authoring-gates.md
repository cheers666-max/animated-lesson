# 交付门禁与失败模式库

这份文档回答一个问题：**凭什么说这份课件做完了？**

答案不是"我看了一遍觉得还行"，而是 `node scripts/verify.mjs` 全绿。下面每一条门禁都对应一类真实会发生的失败 —— 包括本 skill 自己在开发过程中踩到的。

---

## 一、门禁清单

| 门禁 | 断言 | 抓什么 |
|---|---|---|
| **G0** dead-css | `engine/scene.css` 里的每个 `#id` 必须在启动时的 DOM 里存在（十六进制颜色不算） | 选择器写错 → 元素丢掉定位样式、退化成 grid 行、把舞台挤变形。**这条门禁的由来是一次真实事故**：`#caption` / `#scene-tag` / `#bar` 三个 id 写错（引擎建的是 `deck-*`），舞台顶部被 `overflow:hidden` 裁掉 17px |
| **G0b** theme | `meta.theme` 落到 `#deck-app`，且舞台/控制条/字幕条解析出的 `--bg` 一致 | 半截主题：浅色舞台配深色控制条（覆盖层在 `#stage` 外面） |
| **G1** boot | 页面能起来、`DECK_INFO` 就绪、`validate()` 无 error、console 无 error | 语法错、CDN 挂、初始化顺序错 |
| **G2** overflow | 4 个关键帧 × 每幕，所有可见元素的 `getBoundingClientRect` 都在视口内（±3px） | 元素跑出画面（百分比手滑、`h` 太大） |
| **G2b** clip | 文本/列表/代码/大数字的 `scrollHeight ≤ clientHeight + tol` | **盒子里文字被裁掉** —— 看不到图的作者最容易漏 |
| **G2c** overlap | 文字层之间重叠面积 > 8×8px 报警 | 两段字压在一起 |
| **G2d** occlusion | 三类实测：① 字幕条/面包屑/控制条与任何元素**实际墨迹**的相交面积 = 0；② 同一画布内两个 `ink.label` 占位盒不相交；③ 标注不被画布边缘裁掉。探测点必须包含**每条旁白的时刻**（字幕只在旁白窗口可见） | 「看起来有点遮挡」的全部三类。旧版 G2c 只比文字元素的**布局盒**，画布内标注与覆盖层完全没覆盖到 |
| **G5b** caption-line | 字幕恒为单行（用 Range 数真实行盒） | 字幕换行 → 它占的安全带高度随文案变化 → 作者没法定安全区 |
| **G11** data-sensitive | 扰动元素声明的 `data`（数值 ×1.6；若无数字则做结构扰动：数组去掉最后一项），画面必须跟着变 | **装饰性画面**：坐标硬编码的比例图，看着像回事但读不出任何一个值。上线时元课件 7 块画布全部被判为"无法证明承载信息" |
| **G3** animate | 每幕 `t=早` 与 `t=晚` 的截图必须不同 | **静态 PPT 冒充动画** |
| **G3-3d** | 3D 元素区域**裁剪截图**早晚必须不同、且截图不能过小 | WebGL 上下文失败黑屏、3D 没动 |
| **G4** determin | 同一 `t` 渲染两次（间隔 400ms）截图**逐字节相同**；canvas2d 再加像素签名 | `Date.now` / `Math.random` 污染 |
| **G5** caption | 每条 `speak` 在其 `at+0.6s` 时字幕已显示且文字完全一致 | 旁白与字幕错位 |
| **G6** quiz | 有题的幕：选项数正确、点选标出对错、答错显示 `why`、有"继续"按钮、答案被记录 | 预测题点了没反应 |
| **G7** canvas | 每个 canvas2d 的平均 alpha > 0 | `draw()` 没画东西 / 画到画布外 |
| **G9** throttle | 用纯函数探针扫完每一幕：每 0.5s 窗口内首次出现的**信息单元** ≤ 3 | 一页 8 个元素同时弹出（认知过载） |
| **G9b** pacing | 逐帧统计「同时有几笔在生长」：峰值 ≤ 4；生长时长占比 > 85% 报警 | 一次画太多笔 / 一直在画没停顿 |
| **G10** monotonic | 标记 `monotonic: true` 的画布：**可见笔画总长度只增不减** | 画好的东西被擦掉、闪烁、画反 |
| **G8** offline | `?three=off` 重载后：3D 元素 `data-fallback=1` 且**仍在动** | CDN 挂了就开天窗 |
| **FRAMES** | 导出帧序列 + 打印 ffmpeg 命令 | 视频链路是否真的通 |
| **MP4** | `--mp4=out/x.mp4`：帧**不落盘**，直接管道进 ffmpeg | 一键出片；高清导出用「1280×720 设计视口 + DSF 超采样」，而不是把 1280 放大 |
| **G12** | 出片后 ffmpeg 取两帧，量字幕带的亮度：**旁白时刻必须明显亮于无旁白时刻** | 「声称字幕已烘焙、其实成片里没有」。这类"声称有、其实没有"只能靠量来防 —— 早期 capture 模式确实把字幕藏了 |

静态门禁（`node scripts/lint-scenes.mjs`，毫秒级，作者循环里跑）：

- 复用 `validate()` 全部规则（与运行时同源）
- **源码级扫描** `Date.now` / `Math.random` / `performance.now` / `new Date`
- 必须导出 `PROVENANCE`（数字要有出处）

## 二、为什么用"截图字节比较"而不是解码像素

不引入任何依赖（无 sharp / 无 pngjs / 无 canvas），却能**同时覆盖 DOM、canvas2d、WebGL 三种载体**：

- 同一 `t` 两次截图 base64 完全相同 → 渲染确定。
- 不同 `t` 截图不同 → 确实在动。
- 裁剪到 3D 元素矩形 → 定位到具体元素的 3D 问题。

代价：截图必须是同一浏览器同一进程；两次截图之间不能有真实的动画时间流逝（所以 seek 之后要等两帧 rAF 让合成器提交）。

## 三、失败模式库（含本 skill 开发时的真实踩坑）

### A 类：内容与节奏

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| A1 | 画面讲完了，旁白还在说 | 旁白字数 / 4.6 > 剩余时长 | 校验器直接报错。删字、或加 `duration`、或把 `speak` 提前 |
| A2 | 旁白说完了，画面干等 3 秒 | 动作排得太早 | 给最后一个动作加 `wait`，或把 `speak` 往后挪 |
| A3 | 一页 6 个要点全 reveal，像 PPT | 没做注意力管理 | 用 `spotlight` / `dim` 分批；一页最多 3 个视觉焦点 |
| A4 | 数字滚动太快看不清 | `countUp` 的 `dur < 0.4s` | 0.6–1.2s；大数字配 `decimals: 0` |
| A5 | 打字机一次打 60 个字 | 文本太长 | 打字机只用于短标签（< 20 字） |
| A6 | 一页讲 90 秒 | 没有单场景上限 | 硬上限 60s（校验器报错），超了就拆幕 |

### B 类：布局（看不到图时最容易翻车）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| B1 | 元素跑出画面右下角 | `x + w > 100` | 校验器报错；两栏布局用 `4/44` + `52/44` |
| B2 | 列表最后一条被裁掉 | 盒子 `h` 是固定百分比，内容比它高 | G2b 抓；调 `h` 或删条目 |
| B3 | 两段文字叠在一起 | 两栏都从 `x=4` 开始 | G2c 抓 |
| B4 | 大数字和它的 label 挤在一起 | metric 没给足高度 | metric 高度按 `font-size 62px + label` 估，`h ≥ 16` |
| B5 | 换台机器全乱了 | 用了 px 而不是百分比 | 只用百分比；设计坐标系固定 1280×720 |

### C 类：确定性

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| C1 | 同一帧每次截图都不一样 | 场景里用了 `Math.random()` | lint 源码扫描 + G4 行为验证；改用 `sin(i*127.1)` 式确定性伪随机 |
| C2 | 拖动进度条时画面抖动 | 动画依赖"已经跑了多久"而不是 `t` | `draw(ctx, t, ...)` 里只能读 `t`，不能累加 |
| C3 | 导出视频有跳帧闪烁 | 同上 | G4 全绿才导出 |

### D 类：3D 与依赖

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| D1 | 断网 / 内网播放时 3D 区域空白 | three 从 CDN 加载失败 | 必须写 `fallback.boxes`；G8 强制检查 |
| D2 | 3D 区域黑屏 | WebGL 上下文创建失败 | 降级路径覆盖；G3-3d 的"截图过小"断言抓 |
| D3 | 3D 场景与 2D 讲的是两件事 | 两套动画逻辑各写一遍 | 抽一个共享的 `xxxAt(t)` 时间表，两个后端共用（见 `templates/scenes.instancing.js` 的 `submissionAt`） |
| D4 | `import * as THREE` 破坏懒加载 | 场景数据里直接 import | 只用 `init(THREE, ...)` 注入的 THREE |

### F 类：逐笔节奏（「按笔画」专属）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| F1 | 同时有 5 条线在长，眼睛不知道看哪 | 没有笔速预算 | 峰值 ≤ 2 笔（G9b）；其余笔等前一笔画完 |
| F2 | 一整幕都在画，观众喘不过气 | 生长占比 > 85% | 留 ≥15% 静止；画完关键一笔后停 0.3–0.5s |
| F3 | 单笔 0.2s 一闪而过 | 笔速太快 | 单笔 0.4–1.2s；总进度用 `draw` 的 `dur` 控制 |
| F4 | 笔尖"啪"地消失 | 笔画完成瞬间直接不画 nib | 最后 14% 淡出（`fade = clamp01((1-local)/0.14)`） |
| F5 | 画好的东西又没了 | 进度不是单调函数 | 标 `monotonic: true` 交给 G10；检查 `t` 推的进度有没有折返 |
| F6 | 逐笔了一堆并列数据，观众等得烦 | 内容没有顺序信息 | 见 CASE 5：并列信息一次给完 |

### E 类：数据诚实

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| E1 | 正文里的数字找不到出处 | 凭印象写数 | 导出 `PROVENANCE`，每条 claim 指向具体结果文件或教材 |
| E2 | 把某台机器的结论当普遍规律 | 没写测量条件 | 页面上直接标来源（如"本机实测，Apple M5 Pro / Chrome 153"） |
| E3 | 只讲收益不讲拐点 | 讲成了广告 | 必须有"什么时候不该用"这一幕（本模板第 5 幕） |

## 四、作者循环（推荐节奏）

```bash
# 1. 边写边校验，毫秒级反馈
node scripts/lint-scenes.mjs templates/scenes.mine.js

# 2. 写完一幕就上浏览器验，全量约 1–2 分钟
node scripts/verify.mjs --deck=templates/deck.mine.html

# 3. 逐条修到全绿，然后导出视频
node scripts/verify.mjs --frames=out/frames --fps=24
ffmpeg -framerate 24 -i out/frames/f%05d.png -pix_fmt yuv420p -c:v libx264 -crf 20 out.mp4
```

**先跑 G1+G3，再管 G2b。** 课件起不来的时候，纠结 5px 的裁切没有意义。
