# 与 PPT 技能的对照：动画课件该补什么、该守什么

> 问题：*"主要是想结合 PPT 的用法，但我更偏向动画这种、有点区分度。怎么优化？"*
> 这份文档是**逐条对照**的答案，不是泛泛而谈。
> 对照对象：`ppt-master`（代码驱动生成 .pptx，8 步流程）。

## 一、先说结论

**不要把 animated-lesson 做成"另一个 PPT 生成器"。**
它已经有的三件事是 PPT 技能做不到的，那才是区分度所在：

| 能力 | ppt-master | animated-lesson |
|---|---|---|
| 自检方式 | **靠模型逐张看图**（脚本渲染成 jpg 再看） | **21 项门禁**（DOM / 像素 / 时间轴断言） |
| 时间维度 | 静态页 | **确定性时间轴** `render(t)`，可拖、可断言、可出片 |
| 认知管理 | 无 | G9 信息节流（≤3 单元/0.5s）、逐笔、注意力预算 |
| 观众参与 | 无 | 预测题 + 交互式暂停 |
| 依赖 | pptxgenjs + LibreOffice + poppler | **零 npm 依赖**（Node + Chrome） |

**所以优化方向是"把 PPT 的素材能力接进来，把动画的区分度守住"**，而不是把动画砍掉去换 .pptx。

## 二、逐条对照 ppt-master 的 8 步

| ppt-master 的步骤 | animated-lesson 之前 | 现在 | 差距性质 |
|---|---|---|---|
| **0 环境自检** | `serve.sh` + Chrome 检测 | 同 | ✅ 相当（我们更轻） |
| **1 需求澄清**（用途 / 页数） | ❌ 没有 | ❌ 没有 | 🟡 该补，但要换成"**时长 + 信息密度**"而不是页数 |
| **2 资料研究**（硬事实、交叉核对） | ❌ 没有（靠人） | ❌ 没有 | 🟡 这是 **agent 的活**，不该塞进 skill；但该给"事实清单 → 幕"的接口 |
| **3 图片下载**（真实图、验证、占位降级） | ❌ **完全没有** | ✅ **`image` 元素 + G13** | 🔴→✅ 本轮补上 |
| **4 内容架构**（13 页骨架） | ⚠️ `from-md` 按 h2 切幕 | ⚠️ 同 | 🟡 缺"叙事骨架"（开场→故事→人→思想→手法→收尾） |
| **5 视觉系统**（3 色语义配色、字号阶梯） | ⚠️ 只有 3 套固定主题 | ⚠️ 同 | 🟡 该支持"从内容/品牌推导配色" |
| **6 写脚本生成** | ✅ 声明式 DSL（比 pptxgenjs 的红线好守） | ✅ | ✅ 我们更强：DSL 由 `validate()` 静态检查 |
| **7 渲染自检迭代** | ✅ 21 项门禁 | ✅ | ✅ **我们更强**：不依赖"模型能看图" |
| **8 交付 .pptx** | ✅ .pptx | ❌ HTML + mp4 | 🔴 交付格式缺口 |

### 关键判断：第 7 步是我们的护城河

ppt-master 的自检是「渲染成图片 → **用视觉能力逐张看**」。这条路有两个隐患：

1. **模型看图不可靠**：小字溢出、8px 的重叠、对比度不足，看图经常漏；
   而且 ppt-master 自己的文档里就写了「若当前模型/工具无法读图，明确告知用户，不要谎称已检查」——
   说明这个风险是已知的。
2. **不可回归**：这次看出来了，下次改一行脚本，得重新看一遍；没法进 CI。

animated-lesson 的门禁是**可回归、可进 CI、不依赖看图**的。
这是"动画课件"比"PPT 生成器"更容易做对的地方，**不能为了对齐 PPT 流程而放弃**。

## 三、本轮补上的：`image` 元素 + G13

PPT 里图片是主角，而我们之前 **0 图片支持** —— 这是最硬的结构性缺口。

### 用法

```js
{ id: 'ph', type: 'image',
  src: './assets/brush.jpg',   // ⚠️ 相对 deck.html，不是相对场景文件
  fit: 'cover',                // cover 裁切 / contain 完整
  ken: 0.14,                   // 确定性缓慢推近幅度 0~0.6
  bleed: true,                 // 出血背景（满幅），显式声明才豁免安全区
  credit: 'Elstner Hilton, 1911 · Wikimedia Commons · CC BY 2.0' }

// 让它动起来：draw 把 p 从 0 推到 1
{ at: 0.9, action: 'draw', target: 'ph', dur: 16 }
```

### 三个设计决定，都是为了"守住动画的区分度"

**① 推近用 `state.p` 驱动，不用 CSS animation。**
`1 + ken * ease(p)` 是 `t` 的纯函数 → 可拖到任意时刻、逐帧导出不闪、可被 G4 断言。
CSS animation 有自己的时钟，逐帧 seek 时取不出进度 —— 那正是 G4 会随机变红的来源。

**② 缺图不能开天窗。**
加载失败时画虚线占位框 + `data-placeholder="1"`，并且 **G13 直接报红**。
ppt-master 是"自动画占位框，交付时说明"；我们更严：**缺图不允许交付**。
因为动画课件的成品是一段视频，一段带空框的视频比一份带占位框的 PPT 更难补救。

**③ `credit` 必填（校验器 error，不只是 warning）。**
出处标在**画面上**（右下角小字），不是只写在交付说明里。
ppt-master 也要求标来源，但它是写在文档里的；做成视频后，"说明"很容易和成品分离。

### 新增的 `bleed` 概念

满幅背景图在 PPT 里完全正常，但安全区规则（内容 ∈ [3%, 92%]）会拦住它。
解决办法不是放宽规则，而是**要求显式声明**：

```js
{ id: 'ph', type: 'image', bleed: true, x: 52, y: 0, w: 48, h: 100, ... }
```

- `lint-scenes.mjs`：`bleed: true` 跳过安全区检查
- `G2d`：`bleed` 元素不参与"覆盖层压内容"（字幕自带底色药丸，压住背景图不算遮挡）
- 引擎：`bleed` 用在 `text/list/code/metric` 上报错 —— 内容出血会被字幕条压住

**显式声明的意义**：铺满是作者的决定，不是漏写了 `y`。

## 四、还没补的，以及优先级

| 缺口 | 为什么值得做 | 成本 | 优先级 |
|---|---|---|---|
| **PPTX 导出** | 唯一真正的交付格式缺口。做法：每幕导一张静态帧当页 + 旁白进"演讲者备注" + 可选嵌入 mp4 | 中（pptx 就是一个 zip + XML，可以零依赖手写） | **P0** |
| **需求澄清** | 问"用途 + 时长预算 + 信息密度"，而不是页数 | 小 | P0 |
| **从内容/品牌推导配色** | `meta.palette` 覆盖任意 token，`from-md --brand=#1f6feb` | 小 | P1 |
| **叙事骨架** | `from-md` 现在按 h2 机械切幕；该给"开场→…→收尾"的可选骨架 | 中 | P1 |
| **演讲者备注 / 提词器** | 现场讲的时候要看稿 | 小 | P1 |
| **结构图零件库** | ppt-master 有流程图/关系图/三角图/时间线四件套；我们只有 canvas2d 自由画 | 中 | P2 |
| **事实清单接口** | 研究是 agent 的活，但"事实清单 → 幕"的接口该有 | 小 | P2 |

**明确不做**：多模型生成平台、富文本拖拽编辑器、有状态动画、幕间转场。
理由见 `design-notes.md` 与 `skill-roadmap.md`。

## 五、一句话判据

优化这个 skill 时问：

> **这个改动是让"动画"变成负担，还是让"动画"变成别处给不了的东西？**

PPT 技能能给静态页，能给 .pptx，能给漂亮的排版。
**它们给不了的是"这件事是怎么一步步发生的"** —— 逐笔、注意力预算、可拖的时间轴、可断言的确定性。
所以补 PPT 的能力（图片、配色、导出、骨架）时，凡是会削弱时间轴确定性的方案，一律不采纳。

## 六、复现

```bash
cd ~/.agents/skills/animated-lesson

# 图片链路 + G13
node scripts/verify.mjs --deck='templates/deck.html?scenes=./scenes.photo.js'

# 验 G13 真的会失败（一个不会失败的门禁不是门禁）
sed "s|./assets/brush.jpg|./assets/nope.jpg|" templates/scenes.photo.js > /tmp/bad.js
cp /tmp/bad.js templates/scenes.bad.js
node scripts/verify.mjs --deck='templates/deck.html?scenes=./scenes.bad.js'   # → G13 报红
rm templates/scenes.bad.js

./scripts/check-all.sh    # 6 份课件 × 21 项门禁
```
