# skill 的优化路线图

> 这份文档回答的是「**这个 skill 本身怎么优化**」，不是「某一份课件怎么改」。
> 起点是 2025-09 的一次自检：用户看了元课件说"内容好像都比较简单"，
> 追下去发现根因不在课件里，在 skill 的结构里。

## 一、诊断：先看能力矩阵，别看单份产出

skill 当时的真实能力（量出来的，不是印象）：

| 环节 | 现状 | 证据 |
|---|---|---|
| **输入**（素材 → 课件） | ❌ **不存在** | `scripts/` 只有 lint / verify / check-links，没有生成器；4 份课件全是手写 |
| **结构**（教学骨架） | ⚠️ 有 DSL，没有"论证"概念 | `validate()` 管的是坐标/时长/动作合法性，不管"这一幕有没有说服力" |
| **画面**（动作库） | ⚠️ 11 个原子 + 4 个编排 | `ACTIONS` = reveal/fadeOut/spotlight/flash/dim/moveTo/morph/countUp/draw/grow/wait |
| **画面**（载体） | ✅ 9 种元素 + 3D + 2D 降级 | text/shape/annot/code/metric/list/chart/canvas2d/three |
| **音频** | ❌ 只有字幕 | 导出 mp4 无音轨（`speechSynthesis` 只在浏览器里实时念，录不下来） |
| **主题** | ⚠️ 3 套 token，接线有洞 | `paper`/`neon` 定义在 CSS 里，但 `data-theme` 只挂在 `#stage` → 控制条/字幕条不跟 |
| **复用** | ❌ 复制模板 | 没有片段/组件/跨课件共享 |
| **交互** | ⚠️ 只有预测题 | 没有"停下来让观众想"、没有分支 |
| **门禁** | ✅ 16 项浏览器 + 静态 lint | 视觉/技术层面很硬 |
| **教学效果门禁** | ❌ 不存在 | 门禁能证明"没坏"，不能证明"讲清楚了" |
| **反馈闭环** | ❌ 不存在 | 预测题答对率没有回流给作者 |
| **生态** | ⚠️ 只写在文档里 | 与 ppt-master / learn.html 的分工写了，但没有转换器 |

**结论**：这个 skill 是个**做得很硬的渲染引擎 + 门禁系统**，
但它**缺一条从"材料"到"课件"的链路**，也**缺"教学"这一层的抽象**。
所以每一份课件都从空文件手写 → 作者的时间全花在坐标和画布上 →
内容自然停在"能跑、能过门禁"的水平，也就是"简单"。

> 一句话：**不是内容简单，是 skill 把作者的注意力引到了错误的地方。**

## 二、这次已经做的（P0，已落地并有门禁）

### 1. `scripts/from-md.mjs` —— 补上缺失的前端

把一份 Markdown（文档/论文笔记/复盘）变成**能跑、能过全部 16 项门禁**的课件骨架：

- 按 h2 切幕；每幕自动搭出 **主张（原文首段）/ 机制（列表、代码）/ 量级（抽出的数字）/
  边界（"但是、除非、只在"那几句）/ 溯源（claim → 原文 `file:line`）**
- 每幕给一块**通用数据柱状图**（`drawAutoBars`）—— 开箱即 data-driven，所以**天生过 G11**
- 不做改写、不设计画面、不判断哪段值得讲；**它把"待你补齐"的清单打印出来**

验收（实测）：`optimization-checklist.md` → 4 幕 / 1.5 分钟 / 抽出 88 个数字，
其中 30 个带参照、4 幕有边界，**生成的骨架一次通过全部 16 项门禁**。

这一步的价值：作者从"面对空文件"变成"面对一份能跑但还薄的东西 + 一份缺项清单"，
注意力被强制推到"哪一幕没有量级/没有边界"上。

### 2. 内容深度变成可测（`lint` 体检表 + `G11`）

- `lint-scenes.mjs` 每份课件输出一张 **内容深度体检表**：每幕的
  `数字 / 参照 / 边界 / 数据画面 / 预测题`，缺什么直接列出来
- **G11 画面必须对数据敏感**：把元素声明的 `data` 做扰动（数值 ×1.6；分类数据去掉最后一项），
  画面必须跟着变。**装饰性画面（坐标硬编码）会被直接抓住**
  - 这条门禁上线时，元课件 7 块画布**全部**被标记为"无法证明承载信息"

为什么这是关键：它把"内容简单"从主观抱怨变成了**可执行的清单**。
现在元课件的 8 幕全部 5 项达标，而它上线时是 0/8。

### 3. `pause` 动作 —— 交互式暂停

`{ at, action: 'pause', hint: '你最近一次讲的东西，有顺序吗？' }`
播放到点自动停、显示问题、点击继续。**只在播放时触发**，
所以 seek / 逐帧导出（确定性链路）完全不受影响 —— 实测停在 t=26.5 且 hint 正常。

教学价值：这是唯一能让观众**先想再看**的手段。之前的 11 个动作全是"给信息"。

### 4. 顺手修掉的两个真 bug（都是门禁抓出来的）

- **三个 id 写错**：`scene.css` 写 `#caption` / `#scene-tag` / `#bar`，
  引擎建的是 `deck-caption` / `deck-tag` / `deck-bar`
  → 三个覆盖层丢掉定位样式、退化成 grid 行 → **舞台被挤掉 34px、顶部被裁 17px**
  → 新增 **G0 死选择器门禁**（CSS 里的 `#id` 必须在 DOM 里存在）
- **主题半截**：`data-theme` 只挂 `#stage`，控制条/字幕条不跟 → 新增 **G0b**

## 三、路线图

### P0（接下来就该做，成本小、收益大）

| 项 | 为什么 | 怎么做 | 验收怎么量 |
|---|---|---|---|
| **`diff` / `compare` 动作** | 教学里最值钱的动作是"对照"（改前 vs 改后、A 方案 vs B 方案）。现在只能靠摆两个元素，没有"差异高亮" | 编排动作：把两个 target 定位到左右、画中缝、把差异区域框出来 | 新增课件用得上；G2d 断言中缝不压内容 |
| **`pause` 进 lint 的深度表** | 让"这一幕有没有让观众想一下"变成可查的 | 体检表加一列 | 每份课件至少 1 个 pause |
| **`from-md` 支持 h3 合并** | 现在 h2 切幕，长文档会切出 20 幕 | `--merge-h3`：h3 合并进父幕当列表 | 在 webgpu 的两份文档上跑通 |

### P1（做完 P0 之后）

| 项 | 为什么 | 怎么做 | 验收怎么量 |
|---|---|---|---|
| **音频轨** | 导出 mp4 无声音，是交付上最明显的短板 | macOS：`say -v Tingting` 逐条合成 → 按 `speak.at` 用 ffmpeg `adelay`+`amix` 对齐 → 与视频 mux。**非 macOS 降级为不合成并明确告知** | 导出的 mp4 有音轨；`ffprobe` 显示时长与视频一致；每条旁白起点误差 < 0.3s |
| **片段复用** | 四份课件里"两栏对照""柱状图"这类结构重复写了 4 遍 | `el.fragment: 'two-col'`，或 `templates/fragments/*.js` 导出元素数组 | 抽掉重复代码；lint 报出可复用的重复结构 |
| **主题系统补完** | 只有 3 套；没有"品牌色注入" | `meta.theme` 支持对象（覆盖任意 token）；`from-md --brand=#1f6feb` | G0b 扩展到任意 token；新增一套主题 |
| **教学效果门禁（观众视角）** | 现在的门禁证明"没坏"，不证明"讲清楚了" | 预测题答对率回流：`deck.quizAnswers` 落到 localStorage；`verify --audit` 汇总；把"某一幕答错率 > 60%"报成内容问题 | 有真实的答错率数据；能指认"哪一幕没讲清" |

### P2（想做但不急）

| 项 | 为什么 | 备注 |
|---|---|---|
| **PPTX → deck 转换** | 让已有 PPT 能升级成动画课件 | 需要解析 pptx（`unzip` + XML），把每页转成一幕。**工作量最大，收益不确定** |
| **deck → PPTX 导出** | 有人就是要 PPTX 交付 | 与 `ppt-master` 的边界要重新划：静态截图 + 备注放旁白，可能比不做更诚实 |
| **分支 / 观众选择** | 让课件能按观众身份走不同路径 | 会破坏"单条确定性时间轴"这个核心不变量 —— 需要认真设计（每个分支一条时间轴？） |
| **公式排版** | 数学课件需要 | 零依赖做法：用 canvas2d 画（作者自己写），或内联 SVG。**不引入 KaTeX** |
| **表格元素** | 并列数据现在只能用 list | 低优先：`list` + 等宽字体已经够用 |

### 明确不做（以及理由）

- **多模型 / 多 agent 生成平台**：瓶颈是"判断该讲什么"，不是生成吞吐（见 `design-notes.md`）
- **富文本拖拽编辑器**：课件是**代码**，这是它可 diff、可 lint、可被门禁管的前提
- **有状态动画**（`Date.now()` 驱动的粒子、物理引擎累积状态）：会毁掉确定性时间轴，
  而确定性是 scrub / 断言 / 出片 / 可复现四件事的共同基础
- **幕间转场**：会掩盖内容，也让确定性截图对比变复杂
- **为"深度"而堆字数**：深度是**论证链完整**（主张→机制→量级→边界→推论），不是篇幅

## 四、一条判断标准

优化这个 skill 时，问一句：

> **这个改动是让作者更容易"把该讲的讲清楚"，还是只是让工具更花哨？**

内容深度的三条硬指标（已经在 lint 里了）：**有数字、数字有参照、有边界**。
任何新功能如果帮不上这三条，优先级就该往后排。
