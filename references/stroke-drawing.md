# 「按笔画出来」模式参考

> 一句话：**静态图只能给结果，逐笔画能给出过程。而有些知识，过程本身就是知识。**

这份文档讲清三件事：什么时候该用、怎么设计、怎么被验证。
所有结论都对应 `scripts/verify.mjs` 里一条可执行的门禁，或 `templates/scenes.strokes.js` 里一个能跑的例子。

---

## 一、核心抽象：12 行

```js
function drawStrokes(ctx, strokes, p, ink, pal) {
  const total = clamp01(p) * strokes.length;          // 总进度 → 第几笔
  strokes.forEach((st, i) => {
    const local = clamp01(total - i);                 // 第 i 笔自己的进度
    if (local <= 0) return;
    const head = st.cubic ? ink.cubic(ctx, st.cubic, local, o)
                          : ink.path(ctx, st.pts, local, o);
    if (local < 0.999) ink.nib(ctx, head, o.color);    // 只有"正在画的那一笔"有笔尖
  });
}
```

**画面 = f(笔画序列, 进度)。**

这个抽象的四个性质，正是整个模式的价值来源：

| 性质 | 为什么重要 |
|---|---|
| 进度是**输入**不是时钟 | 可 scrub、可跳帧、可截图断言、可导视频 |
| 笔画**按序**出现 | 观众看到的是构造顺序，不是一张已经画好的图 |
| 笔尖只出现在**正在画的那一笔** | 观众始终知道"现在画到哪" —— 这是这个模式的招牌 |
| 只增不减 | 已经画好的东西不会消失，观众的短期记忆不用重载 |

`ink` 工具箱（`engine/scene.js` 的 `makeInk()`）提供 `path` / `cubic` / `quad` / `line` / `arrow` / `dot` / `ring` / `nib` / `label`，全部接受进度 `p`，全部返回**笔尖坐标**。

## 二、五个 case：为什么必须逐笔

### CASE 1 · 结果 vs 过程（立论）

同一张图（控制多边形 + 由它决定的曲线），左边一次给完，右边 8 秒逐笔画出。

**像素完全相同。** 差别只有一件事：**信息什么时候到达观众眼前**。

- 一次给完：观众自己找顺序，注意力随机分配，看到的是"一张图"。
- 逐笔给出：顺序由你控制，注意力跟着笔尖走，看到的是"一个过程"。

这条对比是本模式的立论，也是它的**唯一正当理由** —— 如果内容没有顺序信息，逐笔只是慢（见 CASE 5）。

### CASE 2 · 构造过程就是知识（de Casteljau）

贝塞尔曲线的定义就是构造过程：

1. 画控制多边形（3 笔，逐笔）
2. 每条线段上按同一个比例 u 取点 → 第一层 Q
3. 同样规则再来一层 → R
4. 只剩一个点 S
5. **让 u 从 0 走到 1，S 扫过的轨迹就是曲线本身**

静态图能给你那条曲线，但给不了"它是被构造出来的"这个理解。而后者才是可迁移的知识 —— 它解释了为什么任意阶都成立、为什么数值稳定、为什么 GPU 用它做曲线细分。

**实现要点**：粗结构用 `beats`（哪几条文字什么时候出现），细节奏用 `t`（多边形→点→层→扫描的阶段划分）。两者都以 `t` 为唯一输入，因此仍然完全确定。

### CASE 3 · 顺序就是知识（A*）

15×9 网格、两道带缺口的墙、起点终点。动画做两件事：

1. **前沿扩散**：按 A* 的展开顺序（`f = g + h` 最小者优先，平局按入队顺序）逐格点亮
2. **回溯路径**：到达终点后沿 `prev` 指针回溯，路径逐笔画出

静态图只能给你最后那条线。**"为什么是这条路"完全藏在访问顺序里** —— 观众要看到搜索被终点"吸"过去、看到墙的缺口把前沿掰弯，才明白启发式在干什么。

**实现要点**：搜索顺序在模块加载时算一次（纯函数），因此确定性成立、可断言、可复现。这是"确定性"和"真实算法"可以共存的关键 —— 别把随机性带进算法，用稳定的平局打破规则。

### CASE 4 · 数学 → 字形（SDF）

字母 A 的距离场：每个像素记录它到最近笔画的最近距离（一个 float）。动画把等值线从外向内收：

- level = 0.92 → 0.02，五圈同心等值线一起收缩
- 收到足够紧时，骨架本身被画成笔画 —— 字形"浮"出来

静态图给你一个字形；动画给你**"字形来自数学"**这件事。而这直接解释了为什么描边、发光、抗锯齿、阴影都能从同一份数据算出来（改一个阈值就换一种效果）—— 这是 GPU 文字渲染的核心。

**实现要点**：距离场在模块加载时算一次（180×101 网格），每帧只做阈值取等值线 + 一次 `drawImage` 放大。逐格 `fillRect` 会慢两个数量级。

### CASE 5 · 边界：什么时候**不该**逐笔

左右对比：

- **A · 有先后关系 → 逐笔**：一个 4 步管线，每个方框是一笔，依赖链看得见
- **B · 只是并列比较 → 一次给完**：4 根柱子，全部同时长出来

判据（写在课件里，也写在下面）：

| 问 | 有 → | 没有 → |
|---|---|---|
| 信息里有"先后/依赖/构造顺序"吗？ | 逐笔（观众跟着推理） | 一次给完（观众要同时比较） |
| 逐笔超过 8 秒还没画完？ | 拆幕，或改成"先给结果再补过程" | — |

> **逐笔的价值是"顺序"，不是"动起来"。没有顺序信息时，动画只是慢。**

## 三、设计规则（可检查的）

| 规则 | 数值 | 对应门禁 |
|---|---|---|
| 同时生长的笔画数 | ≤ 2（硬上限 4） | **G9b** 峰值 growing |
| 单笔时长 | 0.4 – 1.2s（太短看不清，太长像卡住） | G9b 生长时长占比 |
| 每幕要有停顿 | 生长占比 ≤ 85%（留 ≥15% 静止让眼睛跟上） | G9b 警告 |
| 新信息单元释放速率 | ≤ 3 单元 / 0.5s | **G9** |
| 已画好的笔画不许被擦掉 | 可见笔画总长度只增不减 | **G10**（`monotonic: true`） |
| 笔尖收尾 | 最后 14% 淡出（直接消失会"啪"一下） | G10 的锯齿曲线能看出来 |
| 一页的视觉焦点 | ≤ 3 个（用 spotlight/dim 分批） | 人工评审 |

`group` 字段声明**信息单元**：同一栏的标题 + 两个数字是一组，观众感知到的是"一个东西出现了"。G9 按单元而不是按元素计数 —— 否则一次 reveal 一栏 4 个元素会被误判为过载。

## 四、门禁的度量演进（一段真实经历）

G10 想抓的是「**已经画好的笔画不该被擦掉**」。度量方法改了三次，每次都被真实数据打回来：

| 度量 | 结果 | 为什么错 |
|---|---|---|
| alpha 之和 | `fb` 报 8.9% 下降、`casteljau` 报 2% 下降 | 不透明的**笔尖移开**时，压在它下面的半透明线露出来，alpha 之和下降 —— 度量伪影 |
| 像素足迹（alpha ≥ 32 的像素数） | `fb` 通过了，`casteljau` 仍报 0.9% 下降 | 笔尖自己就是一块不透明区域，**它淡出必然减少足迹** |
| **可见笔画总长度** | 全部通过 | 只由笔画本身决定，对光标/光晕/装饰完全免疫 |

引擎因此在 `ink` 里记录了每帧的 `len`（当前可见笔画总长度）与 `cum`（累计画出长度），通过 `deck.state().ink` 暴露。

**这段经历的结论比门禁本身更重要**：度量必须量**你真正关心的那个量**。像素/alpha 是代理量，笔画长度才是本体。代理量会把"光标移动"和"内容被擦掉"混为一谈。

顺带，第一次的锯齿曲线暴露了一个真实的观感缺陷：**笔尖在笔画完成瞬间消失**（`[3841, 4272, 5678, 5171, 8052, 11473]` 这种锯齿）。修法是让笔尖在最后 14% 淡出。这是"门禁产出真实改进"的样本 —— 门禁不只是防回归，它能让作者发现看不见的问题。

## 五、确定性铁律（这个模式下更要命）

场景里禁止 `Date.now()` / `Math.random()` / `performance.now()`。

对「按笔画」来说这不是洁癖：

- 笔画的**顺序**是内容本身。随机顺序 = 每次讲的东西不一样。
- 算法（A* 的展开顺序、距离场的值）必须可复现，否则门禁无法断言、视频无法无闪导出。

需要"随机"时用确定性伪随机（`Math.sin(i * 127.1) * 43758.5453` 取小数），或用稳定的平局打破规则（A* 的 `seq` 计数器）。

## 六、速查：从零做一个「按笔画」的场景

```js
{
  id: 'demo', duration: 20,
  elements: [
    { id: 'k', group: 'head', type: 'text', role: 'kicker', text: 'CASE · 逐笔', x: 4, y: 4, w: 60 },
    { id: 'c', group: 'canvas', type: 'canvas2d', x: 4, y: 16, w: 92, h: 76,
      monotonic: true,                     // ← 声明"只增不减"，交给 G10 守
      draw: (ctx, t, el, api) => {
        const { w, h, ink, palette: pal } = api;
        // 笔画序列
        const strokes = [
          { pts: [[0, h], [w * 0.5, 0]], tone: 'line', dash: [6, 5] },
          { cubic: [[0, h], [w * 0.3, 0], [w * 0.7, 0], [w, h]], tone: 'accent', glow: 12 },
        ];
        // 进度：来自 beats 的 draw 动作（推荐）或直接由 t 推
        const p = api.state.p;
        const total = p * strokes.length;
        strokes.forEach((st, i) => {
          const local = Math.max(0, Math.min(1, total - i));
          if (local <= 0) return;
          const o = { color: pal[st.tone], width: 3, glow: st.glow, dash: st.dash };
          const head = st.cubic ? ink.cubic(ctx, st.cubic, local, o) : ink.path(ctx, st.pts, local, o);
          const fade = Math.min(1, (1 - local) / 0.14);
          if (fade > 0) ink.nib(ctx, head, o.color, 4.5 * (0.65 + 0.35 * fade), fade);
        });
      } },
  ],
  beats: [
    { at: 0.3, action: 'reveal', target: ['k', 'c'], dur: 0.5 },
    { at: 1.0, action: 'draw', target: 'c', dur: 10 },     // ← 逐笔的总进度
    { at: 0.6, action: 'speak', text: '……' },
  ],
}
```
